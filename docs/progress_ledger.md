## NEW binary-format discoveries (2026-07-07 evening, for the skill update)
1. **Blink Speed field**: 3 consecutive f32 slots at `range_anchor+40/+44/+48` (range_anchor = the u32 0x10 marker, i.e. `G2._range_off()`) = Normal/Warning/Critical blink. GUI "500 ms" saves **1.0** (unit unclear; 1.0 blinks at a comfortable alarm rate). Found via GUI probe byte-diff (probe_blink_base.rd vs probe_blink.rd, Text Gauge 39). Works binarily — v5's COOLANT P/OIL P pills blink with `struct.pack_into('<f', g.b, g._range_off()+48, 1.0)`.
2. **Static-text flag**: u32 at `states_end+76` (walk 3 state strings from `_states_off()`, then +76): `0x20400000` = Static Text ON (bound gauge FREEZES at baked text), `0x00400000` = live. probe_base.rd text gauges ship static=ON — any dash rebuilt from that donor must clear bit 0x20000000 on every bound value gauge (`round3_v5.py:set_static_text`). v1-v4 didn't hit this because their donor snapshots had it cleared.
3. **Image-type record subframe fields are POISON to write**: u32 `rect_anchor+72` (subframe index, 1-BASED) and u32s `text_end+104/+108` (grid X/Y counts). Writing ANY of them (even "safe-looking" values) blanks the record and every record painted after it → black dash. (probe4/probe6/probe8 bisects).
4. **The stuck-subframe workaround (how v5's background works)**: the donor Image Gauge 1 (Indicator Light) permanently samples subframe 9 of a 9x6 grid = UV window (u 0.875..1.0, v 0..0.125) of its texture — confirmed with a labeled calibration sheet. You cannot retarget it (see #3; writing the +36 UV quad is harmless but ignored for the crop origin). Fix: ship a **6400x3840 sheet PNG** whose window region x5600..6400, y0..480 IS the 800x480 art (`gen_cf_png.py` writes cf_sheet.png; 8px edge extension pads against filter bleed). Rect writes for type 5: `set_rect_px` (rect1) + identity UV at `rect_anchor+20` are safe; also safe: arr1 blend colors, hash, ranges, decimals.
5. **Image-first paint order WORKS**: [Image Gauge (bg), ...text records..., bar, parked image types] renders fine — the old "image record before text kills everything after" rule was actually symptom #3 (poisoned subframe writes), not ordering. The asset-name→id map tail stays INSIDE the Image Gauge record wherever it is in the order; do not split it off (splitting → whole dash blank).
6. **Asset splice recipe**: header asset = lpstr(name) + u32 size + blob, where blob = `00 00 00 00` + PNG bytes (4-byte prefix included in size). Splicing a different-size PNG over `_indicators.png_` works; all six assets end `AE 42 60 82` + u32 flag (last asset 1, others 0) — leave those alone.
7. **In-app FILE→SAVE truncates to 122 records** (127→122 observed on the blink probe) and re-serializes — never in-app-save a binarily-built dash you intend to keep byte-editing.
